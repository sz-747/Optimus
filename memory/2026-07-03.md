## Decisions

- P4 chrome built as 6 vertical slices, each own commit: xterm terminal (e4d1e89), split chrome (01fbd5a), backend split surface (d7893b9), capacity meter (0dbd1d7), pane-visibility governor (00735f4), sidebar (3b970e5), palette (93f6c8e), toasts (34f7343), contentless fix (7331fc7).
- Split tree drives frontend via command-returns-TreeView, NO event bus — structural ops are the only tree mutators, so each mutating command returns the fresh layout. Frontend re-renders from the return value.
- Pane rects reuse tested backend `compute_leaf_rects` (normalized [0,1]); JS never reconciles a tree. Panes keyed by SurfaceId, moved not recreated (scrollback survives split).
- Pane-visibility manager: WebGL attached only to on-screen panes, budget 12 (WebView2 caps ~16 live contexts). Off-screen panes detachWebgl → DOM renderer; buffer independent of renderer so no history loss.
- Capacity meter DTO mirrors ported CapacityIndicatorViewModel (parity tests). Domain stores capacity Arc to expose capacity_view().
- Toast delivery: Domain holds `Option<Box<dyn Fn(Vec<ToastView>)>>` push sink, installed from a Send Tauri Channel via host.run — keeps the lib tauri-free. record_notification drains + pushes show_toast survivors. Push, not poll.
- Terminal disposal made EXPLICIT (close ops return freed surface ids; frontend reaps exactly those). render() no longer disposes by absence from the selected workspace's tree — that killed other workspaces' terminals on switch.
- Never-contentless invariant enforced: close_surface re-seeds on SplitTreeEvent::Emptied; close_workspace flags the Created replacement. CloseReport/CloseResult carry `reseeded`; frontend backs the fresh surface via spawn.
- fmt discipline: rustfmt only the 3-4 files I touch (never `cargo fmt` — it churns 11 pre-existing unformatted P3 files). Left those as status quo.
